Garanties du Smart Contract
  • Immuabilité : une preuve enregistrée ne peut jamais être modifiée
  • Non-répudiation : msg.sender lie chaque certification à son auteur
  • Horodatage réseau : block.timestamp fourni par Ethereum — infalsifiable
  • Indexation par productId : recherches rapides sans parcourir la chaîne
Smart Contract déployé
pragma solidity ^0.8.19;

contract CertificationRegistry {
  struct CertificationProof {
    string productId;
    string proofHash; // SHA-256
    string ipfsCID; // Photo décentralisée
    string step; // INIT|HARVEST|...
    uint256 timestamp; // Infalsifiable
    address certifiedBy;
  }
}

07 — Sécurité (détail)

C1 → C5
Signature · Stockage · Validation · Anti-rejeu · Intégrité

C1ECDSA P-256Signature des transactions
🔧 Implémentation Web Crypto API · courbe secp256r1
Chaque transaction sensible (certification, paiement, escrow) est signée avec la clé privée de l'utilisateur. La signature est vérifiée côté serveur avant exécution.
Extrait code WebCrypto ECDSA ↑ src="" → URL capture code
C2IndexedDB non extractableStockage sécurisé des clés
🔧 Implémentation extractable: false · IndexedDB
Les clés privées sont stockées dans IndexedDB avec le flag extractable: false. La clé ne peut jamais être exportée en bytes, même en cas de XSS — seul le moteur crypto peut l'utiliser pour signer.
C3Validation serveurRe-vérification ECDSA + ownership
🔧 Implémentation Firebase Cloud Functions · Node.js
Toute opération critique est relayée via une Cloud Function qui re-vérifie la signature ECDSA, valide l'ownership du produit, et applique les règles métier. Le client Angular est une simple interface — jamais une source de vérité.
C4Nonce anti-rejeuPrévention replay attacks
🔧 Implémentation UUID v4 · Firestore TTL 10 min
Chaque message contient un UUID v4 unique (nonce) associé à un timestamp. Le nonce est consommé dans Firestore avec une TTL de 10 minutes. Toute tentative de rejeu échoue avec already-exists.
C5Hash image SHA-256Intégrité des preuves visuelles
🔧 Implémentation Double calcul client/serveur · CryptoJS
Le hash SHA-256 de l'image est calculé côté client avant envoi à IPFS. La Cloud Function re-télécharge l'image depuis IPFS et recalcule le hash. En cas de divergence, la certification est immédiatement rejetée.

07 — Sécurité (suite)

C6 → C10
Ledger · Chiffrement · Escrow · Audit · Rules

C6Ledger chaînéImmutabilité historique
🔧 Implémentation SHA-256 chaîné · nonce · preuve de travail
Chaque événement (certification, paiement, escrow) est enregistré dans un ledger local. Chaque bloc contient le hash du bloc précédent, créant une chaîne immuable. Modifier un bloc casse toute la chaîne qui suit.
Block { previousHash, data, timestamp, nonce, hash: SHA256(prev+data+ts+nonce) }
Capture structure ledger SHA-256
Blocs chaînés ↑ src="" → URL capture ledger
C7AES-GCM + PBKDF2Confidentialité des données
🔧 Implémentation 310 000 itérations · chiffrement symétrique
Les données sensibles sont chiffrées avec AES-GCM. La clé est dérivée via PBKDF2 avec 310 000 itérations (conforme OWASP 2024). Le chiffrement protège les données en transit et au repos.
C8Escrow AGCSéquestre atomique
🔧 Implémentation Transaction Firestore · lock/release
Les paiements en AGC sont gelés dans un séquestre jusqu'à confirmation de livraison. La transaction est atomique : débit et crédit sont exécutés ensemble. En cas de litige, rollback automatique vers l'acheteur.
C9Audit Trail immuableTraçabilité write-only
🔧 Implémentation Write-only Firestore · hash chaîné
Chaque action critique est journalisée dans une collection Firestore en write-only. Les règles de sécurité interdisent toute modification ou suppression. Les logs sont chaînés via SHA-256 pour garantir l'intégrité.
allow create: if request.auth != null;
allow update, delete: if false;

C10Firestore Security RulesPérimètre applicatif
🔧 Implémentation Ownership · rate limiting · immutabilité
Les règles Firestore garantissent qu'un utilisateur ne peut accéder qu'à ses propres données. Le rate limiting (5 opérations/minute) protège contre les abus. Les logs d'audit sont protégés en write-only.
