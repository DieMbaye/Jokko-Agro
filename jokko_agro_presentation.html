Trois défis de l'agriculture sénégalaise
Agriculture en Afrique subsaharienne — enjeux numériques non résolus
Accès à l'expertise
Les agriculteurs, souvent non francophones, n'ont pas accès aux conseils agronomiques. Absence de support Wolof dans les outils numériques existants.
Traçabilité absente

Axe IV — Sécurité multicouche

4 couches de défense

C1
🔐 IndexedDB non extractable
AvantsessionStorage — lisible par tout script JS (XSS = vol de clé)
AprèsCryptoKey avec extractable: false dans IndexedDB — la clé ne sort jamais du moteur crypto
"Équivalent logiciel d'un Secure Enclave — même un XSS ne peut pas exporter les bytes de la clé privée."
C2
☁️ Validation serveur (Cloud Functions)
Avant Logique métier dans le client Angular — contournable via l'API Firebase directement
AprèscertifyCheckpoint() re-vérifie signature ECDSA, ownership produit, rate limit — côté Node.js, hors de portée du navigateur
"Le client Angular est une interface, jamais une source de vérité."
C3
🎲 Nonce anti-rejeu
Risque Une signature valide interceptée peut être renvoyée à volonté (replay attack)
Après Chaque message contient un UUID v4 (nonce) + timestamp. Le nonce est consommé en Firestore — tout rejeu échoue avec already-exists
UUID randomUUID()
Fenêtre ±5 min
TTL 10 min
C4
🖼️ Hash image SHA-256 côté serveur
Risque Score TF.js calculé dans le navigateur — modifiable avant envoi
Après Hash SHA-256 calculé avant le scoring. La Cloud Function re-télécharge depuis IPFS et recalcule — hash ≠ → rejet immédiat
"Le score IA est indicative_only — l'intégrité de l'image est prouvée cryptographiquement."

C5 — Ledger immuable · SHA-256 chaîné
interface Block {
  previousHash: string; // chaînage
  blockHeight:  number;
  nonce:        number; // anti-collision

Si block[n].hash ≠ SHA256(data+prev+nonce) → falsification détectée. Modifier un bloc casse toute la chaîne qui suit.

// write-only — JAMAIS modifiable
