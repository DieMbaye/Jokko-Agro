## 🔷 **1. QU'EST-CE QU'UNE SIGNATURE NUMÉRIQUE ?**

### **Définition**
Une **signature numérique** est l'équivalent électronique d'une signature manuscrite, mais en beaucoup plus sécurisé. C'est un mécanisme cryptographique qui permet de **prouver l'authenticité** et **l'intégrité** d'un document ou d'une transaction.

### **Analogie simple : Le cachet officiel avec identifiant unique**
Imaginez que chaque utilisateur possède un **cachet personnel absolument unique** (sa clé privée) et que tout le monde possède un **livre qui permet de vérifier** que le cachet est authentique (la clé publique). Quand quelqu'un envoie un message, il appose son cachet. N'importe qui peut vérifier dans le livre que le cachet est bien le sien.

## 🔷 **2. POURQUOI AJOUTER DES SIGNATURES À NOTRE LEDGER ?**

### **Ce que l'Étape 1 nous a apporté :**
- ✅ Intégrité des données (personne ne peut modifier sans être détecté)

### **Ce qui manque encore :**
- ❌ **Authentification** : Qui a vraiment créé cette transaction ?
- ❌ **Non-répudiation** : L'utilisateur peut-il nier avoir fait la transaction ?
- ❌ **Preuve de propriété** : Comment prouver que c'est bien le propriétaire qui a agi ?

### **Problèmes résolus par les signatures numériques :**

| Problème | Solution |
|----------|----------|
| **Usurpation d'identité** | Quelqu'un peut-il envoyer des AGC en votre nom ? |
| **Répudiation** | Pouvez-vous dire "ce n'est pas moi qui ai fait cette transaction" ? |
| **Authenticité** | La transaction vient-elle vraiment de l'expéditeur affiché ? |
| **Preuve légale** | Une transaction signée a valeur juridique |

## 🔷 **3. LE PRINCIPE DE LA CRYPTOGRAPHIE ASYMÉTRIQUE**

### **3.1 Les deux clés**

Chaque utilisateur possède une **paire de clés** :

```
┌─────────────────────────────────────────────────┐
│            UTILISATEUR (Alice)                   │
├─────────────────────────┬───────────────────────┤
│    CLÉ PRIVÉE 🔐         │    CLÉ PUBLIQUE 🔓    │
│                         │                       │
│  ✓ À GARDER SECRÈTE      │  ✓ À PARTAGER         │
│  ✓ Connue d'Alice seule  │  ✓ Tout le monde peut │
│  ✓ Sert à SIGNER         │    la voir            │
│  ✓ Ne peut être déduite  │  ✓ Sert à VÉRIFIER    │
│    de la clé publique    │                       │
└─────────────────────────┴───────────────────────┘
```

### **3.2 Analogue dans le monde réel**

```
CLÉ PRIVÉE = Votre signature manuscrite + votre carte d'identité secrète
CLÉ PUBLIQUE = Le modèle de signature publié dans un annuaire officiel

Quand vous signez un chèque :
- Votre signature (clé privée) est unique et personnelle
- La banque vérifie avec votre modèle (clé publique) que c'est bien vous
- Vous ne pouvez pas dire "ce n'est pas ma signature"
```

## 🔷 **4. COMMENT ÇA FONCTIONNE DANS NOTRE SYSTÈME**

### **4.1 Processus de signature d'une transaction**

```
ÉTAPE 1 : CRÉATION DE LA TRANSACTION
┌─────────────────────────────────────┐
│ Transaction :                        │
│   De: Alice                          │
│   Vers: Bob                          │
│   Montant: 10 AGC                     │
│   Date: 09/03/2026                    │
└─────────────────────────────────────┘
                  ↓
ÉTAPE 2 : CALCUL DE L'EMPREINTE (HASH)
┌─────────────────────────────────────┐
│ Empreinte numérique :                │
│   "3f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c" │
└─────────────────────────────────────┘
                  ↓
ÉTAPE 3 : SIGNATURE AVEC CLÉ PRIVÉE
┌─────────────────────────────────────┐
│ 🔐 ALICE SIGNE :                     │
│   Empreinte + Clé privée d'Alice     │
│         ↓                            │
│   Signature = "7x8y9z0a1b2c3d4e5f6g" │
└─────────────────────────────────────┘
                  ↓
ÉTAPE 4 : TRANSACTION SIGNÉE
┌─────────────────────────────────────┐
│ Transaction + Signature              │
│   "De: Alice, Vers: Bob, 10 AGC"     │
│   Signature: 7x8y9z0a1b2c3d4e5f6g    │
└─────────────────────────────────────┘
```

### **4.2 Processus de vérification**

```
ÉTAPE 1 : RÉCEPTION DE LA TRANSACTION
┌─────────────────────────────────────┐
│ Transaction reçue :                  │
│   De: Alice, Vers: Bob, 10 AGC       │
│   Signature: 7x8y9z0a1b2c3d4e5f6g    │
└─────────────────────────────────────┘
                  ↓
ÉTAPE 2 : CALCUL DE L'EMPREINTE
┌─────────────────────────────────────┐
│ On recalcule l'empreinte :           │
│   "3f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c" │
└─────────────────────────────────────┘
                  ↓
ÉTAPE 3 : VÉRIFICATION
┌─────────────────────────────────────┐
│ 🔓 ON VÉRIFIE :                      │
│   Signature + Empreinte + Clé publique d'Alice │
│         ↓                            │
│   ✓ VÉRIFICATION RÉUSSIE              │
│   La signature correspond à Alice     │
└─────────────────────────────────────┘
```

## 🔷 **5. ECDSA (Elliptic Curve Digital Signature Algorithm)**

### **5.1 Qu'est-ce que c'est ?**

L'**ECDSA** est l'algorithme de signature numérique que nous utilisons. Il est basé sur les **courbes elliptiques**, une branche avancée des mathématiques.

### **5.2 Pourquoi ECDSA ?**

| Critère | ECDSA | Autres (RSA) |
|---------|-------|--------------|
| **Sécurité** | Très élevée | Élevée |
| **Taille de clé** | Petite (256 bits) | Grande (2048+ bits) |
| **Performance** | Rapide | Plus lent |
| **Ressources** | Faibles | Élevées |
| **Adapté mobile** | ✅ Oui | ❌ Non |

### **5.3 Propriétés mathématiques**

```
La sécurité repose sur le problème du logarithme discret sur courbe elliptique :

Étant donné :
- Un point G sur la courbe (point de base)
- La clé publique P = k × G (k fois le point G)

Trouver k (la clé privée) est MATHÉMATIQUEMENT IMPOSSIBLE
même avec les ordinateurs les plus puissants.

→ La signature est INFALSIFIABLE
```

## 🔷 **8. RÉSISTANCE AUX ATTAQUES - NIVEAU 2**

### **8.1 Attaques désormais impossibles**

| Attaque | Pourquoi ça échoue |
|---------|-------------------|
| **Usurpation d'identité** | L'attaquant n'a pas la clé privée |
| **Création de fausse transaction** | Ne peut pas signer correctement |
| **Modification après signature** | La signature ne correspond plus |
| **Rejeu de transaction** | Le nonce est vérifié + signature |
| **Attaque de l'homme du milieu** | Impossible de modifier sans casser la signature |

### **8.2 Scénario d'attaque déjoué**

```javascript
Tentative de l'attaquant :
"Je vais envoyer 1000 AGC de Alice vers mon compte"

Ce qu'il faut :
1. ✅ Il peut créer la transaction
2. ✅ Il peut modifier le montant
3. ❌ Il ne peut PAS SIGNER avec la clé privée d'Alice
4. 🚫 TRANSACTION REJETÉE

Résultat :
Signature invalide → Transaction refusée
```
